固定演示用户，点击即可体验完整会话流程。

01 · LOGIN

创建一份会话

模拟用户 whb 已通过认证。服务端创建 5 分钟会话，只将随机编号放进 Cookie。

试试 5 秒过期实验 →
POST /login → 303 → GET /session
02 · STATE

换连接，状态仍然在

查看用户名、访问次数、剩余有效期。刷新后访问次数继续增加，它保存在服务端。

查看会话信息
GET /session → 使用编号查表
03 · VERIFY

访问受保护页面

服务端必须找到尚未过期的 Session 才允许访问。仅设置用户名 Cookie 不够。

打开受保护页面
有效会话 → 200 · 无效会话 → 401
04 · LOGOUT

让旧凭据失效

同时撤销服务端会话、删除浏览器 Cookie。即使重新发送旧编号，也不能恢复登录。

POST /logout → 撤销 Session + Max-Age=0

Cookie：继续保留四个小实验

与登录会话相互独立。

01 · SET

记住一个用户名

内容和属性已写在服务端：用户名 whb、主题 blue，默认保留 5 分钟。

demo_user=whb
demo_theme=blue
Path=/ · Max-Age=300 · HttpOnly · SameSite=Lax
POST /cookie/set → 303 → GET /cookie
02 · READ

查看浏览器带回的内容

这里显示服务端从本次请求解析到的 Cookie。刷新页面，会产生一条新请求。

查看本次请求
默认包含 HttpOnly，因此用开发者工具查看它，而不是 document.cookie。
GET /cookie → 读取请求头 Cookie
03 · PATH

只在某些路径携带

设置 demo_path，限定 Path=/a/b，再对比这几个地址。它有独立的 5 分钟有效期。

/cookie/a/b/a/b/inside/a/bc
/a/bc 不属于 /a/b 的路径范围
04 · CLEAR

让浏览器忘记它

服务器发送同名、相同 Path 的 Cookie，并把 Max-Age 设为 0，删除三个演示 Cookie。

POST /cookie/clear → Set-Cookie: ...; Max-Age=0

对照着看这两处

响应的 Set-Cookie 告诉浏览器如何保存；后续请求的 Cookie 只携带名称和值，不带 Path、Max-Age 等属性。

demo_user 是可修改的演示数据，不能证明登录；cpp_session_id 仅用作查表编号。真正的用户名保存在服务端。

本章使用固定用户模拟认证，不是账号系统。Session 保存在内存，服务器重启后失效；HTTP 学习环境暂未启用 HTTPS。
